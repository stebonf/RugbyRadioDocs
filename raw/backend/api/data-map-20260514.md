## AppDbContext (api)

### File sorgente

- `src/RugbyRadio/Lib/Repositories/AppDbContext.cs`

### Responsabilità tecnica

Contesto EF Core principale. Gestisce tutte le entity persistenti della piattaforma su database SQL Server. Registra le conversioni enum→int per `Match.Status`, `MatchEvent.Territory`, `MatchEvent.Type`. Registra conversioni custom (compressione/decompressione) per i campi `Audit.RequestSerialized` e `Audit.ResponseSerialized` tramite `DbConfiguratorHelper.Zip/Unzip`.

## Note finali

- Limiti dell'analisi: i metodi delle repository `SystemMessageDraftRepository`, `CommentRepository`, `EventReactionRepository`, `UserOtpCodeRepository`, `UserTokenRepository`, `BlogRepository`, `AuditRepository`, `EmailRepository`, `FakeAgentSettingRepository` non sono stati letti nel dettaglio; il metodo `GetStatsAsync()` è stato letto solo parzialmente.
- Elementi esclusi: `ChannelUserRepository` (solo operazioni CRUD base non deducibili da lettura); `MatchScoreboard` e `MatchScoreboardAi` (classi nel MatchBox — non deducibile se persistenti o solo model); DTO non persistenti; classi di supporto (`EventReactionCount`, `SystemMessageVersion`, `CheckSentencesAnswer`).
- Elementi non deducibili: nome tabella DB di `MatchLike` (assenza di `[Table]`); nome tabella DB di `Audit`; modalità di hashing password (non visibile nel layer repository/service letto); formato serializzato di `FakeAgentSetting.ViewerIds`.
- ID generazione: il repository base genera `Id` come stringa da 20 caratteri derivata da datetime UTC + GUID, uppercase, senza separatori.
- Soft delete: tutte le entity ereditano `IsDeleted` da `EntityBase`; il filtro `!IsDeleted` è applicato in tutte le query del repository base e override. `DeleteAsync` nel base effettua cancellazione fisica (EF `Remove`); la cancellazione logica non è implementata nel base ma è gestita a livello applicativo dove necessario.
- Wiki non modificata: confermato.
